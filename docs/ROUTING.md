# 单文件通道路由与回执

调用项目填写可读范围和结果目录。桥接器的站点配置提供已配对的剪切板和可选的 Runner。

| 场景 | 选路 |
| --- | --- |
| 用户指定通道 | 只用该通道。offline 只用剪切板。 |
| 混合模式下的小文本 | 优先剪切板。已知的长时间退让可在派发前选用 Runner。 |
| 已知传输量至少 4 MiB，或 PDF、Office | 优先使用支持该文件的 Runner。 |
| 剪切板回执确认未发送 | 在混合模式中，符合分流条件且 Runner 可用时才切换。 |
| 已发送或发送状态不明 | 沿原通道和请求号用 resume 查询。 |

剪切板收发使用其本机互斥锁。Runner 可同时读取另一份独立文件。两条通道均按已登记的路径校验请求，返回文件长度和 SHA256。Runner 还通过原 GitHub Run 的加密 Artifact 及密文摘要核对结果。

单文件读取由传输端点处理。站点若也部署了可由两路派发的 Terminal Worker，Worker 分配取决于对应的站点队列和项目能力。
